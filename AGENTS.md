## Workflow

- Любые изменения кода проекта выполнять через цепочку агентов: writer вносит правки, reviewer проверяет (агент `reviewer`, модель `opencode-go/glm-5.3#high`), при замечаниях — новый раунд writer → reviewer, максимум 3 раунда.
- После правок в `scripts/autoload/` или `scripts/data/` запускать smoke test (см. Commands).
- Агенты должны использовать полный путь к Godot из раздела Repo state, если команда `godot` недоступна.
- Изменения, которые пользователь явно попросил сделать без цепочки, выполнять напрямую.

## Commands

- Run game (windowed): `godot --path "E:\Games\TestGame"` (or open project in Godot editor)
- Headless smoke test (exit 0 = pass): `godot --headless --path "E:\Games\TestGame" "res://tests/smoke_test.tscn"`
- Import/validate project: `godot --headless --path "E:\Games\TestGame" --import`
- Check runtime errors: `godot --headless --path "E:\Games\TestGame" --quit-after 30`
- Build installer (bumps version): `powershell -ExecutionPolicy Bypass -File "E:\Games\TestGame\installer\build.ps1"` (add `-NoBump` to keep version). Exports to `build/windows/Businessman.exe`, compiles `installer/tycoon.iss` → `dist/Businessman-Setup-MAJOR.MINOR.exe`, then writes the next version to `version.txt`.

## Version

- Version lives in `version.txt` (root, `MAJOR.MINOR`, e.g. `0.1`); it is NOT hardcoded in the UI.
- `Version` autoload (`scripts/autoload/version.gd`) reads `res://version.txt` at startup (`get_version()`); the file is shipped via the export preset `include_filter="version.txt"`.
- Main menu bottom-right shows `tr("m_version") % Version.get_version()` small (font 14) — «Версия: 0.1» / "Version: 0.1".
- `installer/build.ps1` reads `version.txt`, writes it into `#define MyAppVersion` in `tycoon.iss`, builds, then increments only the minor part for the next build.
- Window is **fixed at 1280×720**: `project.godot` has `window/size/resizable=false`, `window/size/mode=0`; `Settings.apply()` forces `WINDOW_MODE_WINDOWED`, sets `WINDOW_FLAG_RESIZE_DISABLED` + `WINDOW_FLAG_MAXIMIZE_DISABLED` and re-centers the window. Resolution/fullscreen controls in the settings page are hidden; there is no fullscreen toggle or key binding.

Run the smoke test after any change to game logic (`scripts/autoload/`, `scripts/data/`).

## Structure

- Main scene: `scenes/main_menu.tscn` (menu → `scenes/main.tscn` game screen).
- `scripts/ui/main_menu.gd`: title + buttons centered (`_make_page` VBox `ALIGNMENT_CENTER` full-rect; `_make_button` uses `SIZE_SHRINK_CENTER`); pages built in code via `_make_page`/`_clear` (clears all children except the persistent `delete_confirm` dialog).
- `scripts/autoload/` — I18n, Version, Settings, GameState, Market, TurnManager, AIManager, RandomEvents, SaveManager, SteamAchievements (order matters; registered in project.godot).
- Realistic AI mode (`GameState.realistic_ai`, chosen by the «Реалистичные ИИ игроки» CheckButton on the new-game page with an explanatory note): AI opponents additionally buy cars/properties (`ai_players[].car/property`, `buy_car_for_owner`/`buy_property_for_owner`, `_ai_buy_lifestyle` picks the highest affordable upgrade after trade-in) and get their own random events each turn (`RandomEvents.maybe_trigger_for(owner)`, no popup for AI; effects hit that AI's money/inventory/car and its per-owner `production_multiplier`). Their prestige raises their sales income (`get_owner_income_multiplier`). Saved as `realistic_ai`; load/save slot rows show a gold circled **R** badge with tooltip «Реалистичная игра» when the save is realistic (`get_save_info()["realistic_ai"]`).
- AI (`ai_manager.gd`): strategic investor — `_ai_complete_chain` buys the **highest-level affordable** enterprise for each missing type (max 1/type, so it never triggers antimonopoly), `_ai_deny_player` competes for a high-production enterprise of a type the player owns (production/price score) to block the player, then `_ai_upgrade` reinvests by buying the next level of its own enterprise and selling the old one.
- `scripts/ui/` — main_menu, main_screen, exchange_screen, enterprises_screen, placeholder_art (UI built in code, not .tscn).
- `data/enterprises.json` — balance data: 10 levels × 3 types (price = 400×1.6^(N-1), prod = round(13.5N)..round(15N), e.g. L1 14–15, L10 135–150).
- Enterprises are unique per (type, level): owner stored on `enterprises[].owner`, 0 = player, 1..8 = AI; helpers `get_enterprise_owner`, `is_enterprise_available`, `buy_enterprise(etype, level_data, owner_id=0)`, `sell_enterprise(index, owner_id=0)`, `get_enterprises_of_owner`, `get_enterprises_of_type`, `count_enterprises_of_type`.
- AI (`ai_manager.gd`): 1..8 opponents chosen in main menu; each gets +$50/turn and produces. Investment is strategic, not greedy: first `_ai_complete_chain` (buy the cheapest affordable enterprise for each missing type, so max 1 of any type → AI never triggers antimonopoly), then `_ai_upgrade` reinvests by buying the next level of one of its own enterprises and selling the old one (level-highest value while staying 1/type). `AI_MAX_BUYS_PER_TURN=2` investment actions/turn, keeps `TRADE_RESERVE=$100`. AI trades **exactly like a player** — no restrictions: each turn it first posts its surplus (`_ai_post_lot`: raw kept = `factory_need + 5`, remainder posted; product = half if ≥2, price `base × 0.9..1.3`), then does 1-3 buy actions/turn (`MARKET_ACTIONS_MIN..MAX`, `BUY_MAX_PER_ACTION=10`).
- Market is a **lot order book** (`Market.lots`): sellers escrow goods into a lot `{id, owner, kind, qty, price}`, buyers click a specific lot + qty (partial fills OK), money goes to the seller; you cannot buy your own lot. `post_lot(owner,kind,qty,price)`, `buy_from_lot(lot_id,buyer,qty)`, `cancel_lot(lot_id,owner)` (returns remainder), `get_lots`/`get_lots_of_kind`/`get_lots_of_owner`, `get_best_price(kind)` (cheapest lot or base), `get_price`, `get_base_price(kind)`, `reset()`, signal `lots_changed`. `BASE_PRICE` (raw 10 / product 20) is only the sales-enterprise payout and the AI/reference price.
- Random events (`RandomEvents`): 10% chance per turn, uniform pick of 12 events (7 positive / 5 negative), player-only; money/inventory multipliers apply immediately, production ×2 / ×0.5 sets `GameState.production_multiplier` consumed by that same turn's player production (`_advance_turn` triggers events **before** `produce_for_owner(0)`); `car_broken` is a no-op placeholder until machines exist. `RandomEvents.enabled=false` in smoke tests for determinism.
- Game screen (`main_screen.gd`): top bar = one aligned info row (button "Меню" + `$money` font 20 + `Ход N` font 20 + `Сырьё`/`Товар` font 16, all `SIZE_SHRINK_CENTER`, centers within 0.5px), spacer, then AI standings (color, number, money) on the right in a 2-column `GridContainer` (max 4 rows, so 8 AIs do not push the end-turn button off-screen). Action buttons (Работа/Биржа/Предприятия/Недвижимость/Автомобили + ЗАВЕРШИТЬ ХОД full-width; 3 buttons per row, left-aligned) are bottom-right (`SIZE_SHRINK_END`); there is **no Save button** on the game screen — saving lives in the ESC/«Меню» dialog (borderless, no close button; vertical stack: Save & Exit / Save / Exit / Back, the last button highlighted like End Turn; default OK bar hidden). left area shows `PlaceholderArt` (programmatic `_draw`: gradient sky, moon, skyline with lit windows, "TYCOON"). ESC or "Меню" opens the exit dialog (Save & Exit / Save / Exit / Back); colors from `GameState.AI_COLORS` / `get_owner_color()` (owner 0 = dark blue).
- Enterprises screen is a 3×10 button grid (columns = types, rows = levels; the left column shows production per turn 9–10 … 90–100 (e_prod header), not level numbers; button shows price; `grid` `h_separation=150` spreads the columns, total ≈1013px); its top bar mirrors the other screens: aligned `info_row` with back button top-left (140×44, font 16), title font 30, spacer, money font 20. Unowned cell = gray → buy confirm dialog; own cell = player color → sell confirm dialog; AI-owned cells are colored by that AI and disabled; cells are also disabled when `money < price`. `enterprises_screen.gd` calls `GameState.buy_enterprise(...,0)` / `sell_enterprise(index,0)`; the antimonopoly warning label is hidden until the player owns 2+ of a type.
- Cars (`data/cars.json` + `scripts/data/car_data.gd` `class_name CarData`; `load_cars()`, `get_car(idx)`, `get_car_color(car)`): 8 cars Ока→Bugatti Veyron, strictly ascending `price` and `prestige`, each with `{id, image, price, prestige, color, kind}` (`kind` = boxy/sedan/sport shapes the fallback art, `image` = `res://assets/png/*.png`). `GameState.owned_car` (-1 = none) + `TRAM_FARE=30`, `signal car_changed`; helpers `own_car()`, `get_prestige()`, `get_sales_multiplier()` (= `1 + car prestige/100`, display/tests only), `get_passive_income()` (full-chain estimate × income multiplier), `buy_car(idx)` (spends the price, refunds 50% of the old car as trade-in). Prestige adds to the property prestige (see below); `get_income_multiplier() = 1 + get_total_prestige()/100` scales the player's sales payout in `turn_manager.produce_for_owner` and the passive-income estimate (owner 0 only). Work pay is flat `main_screen.WORK_PAY=50`. Cars screen (`cars_screen.gd` + `cars.tscn`, signal `back_requested`) lists all cars with a `CarArt` (`car_art.gd`, programmatic side-view `_draw`; draws the PNG contain-fitted when present, `kind == "tram"` draws a tram) + buy confirm/info dialogs; reached from the game screen "Автомобили" button (right-hand button column). Opening the exchange with no car charges `TRAM_FARE` in `main_screen._on_open_exchange` (blocked by an info dialog if unaffordable); AI also pays `TRAM_FARE` each turn in `ai_manager._ai_turn`. The main game screen shows the owned car's `CarArt` (or a tram when `not own_car()`) bottom-left; the main menu does not show the car. `car_broken` random event sets `owned_car = -1`.
- Real estate (`data/properties.json` + `scripts/data/property_data.gd` `class_name PropertyData`; `load_properties()`, `get_property(idx)`, `get_property_color(prop)`): 7 properties, strictly ascending `price` & `prestige` — shed (Сарай в поле) → palace (Дворец), each `{id, price, prestige, color, kind, image}` (`kind` = shed/house/flat/cottage/penthouse/mansion/palace; `image` = `res://assets/png/home_<kind>.png`, square 1024×1024). `GameState.owned_property` (-1) + `signal property_changed`; helpers `own_property()`, `get_property_prestige()`, `buy_property(idx)` (50% trade-in, same as cars). Prestige is wired into the economy: `get_total_prestige()` = car + property prestige, and `get_income_multiplier()` boosts the player's sales income by that many percent. Properties screen (`properties_screen.gd` + `properties.tscn`, signal `back_requested`) mirrors the cars screen with `PropertyArt` (`property_art.gd`: draws the `image` contain-fitted (280×280 rows), falls back to a programmatic building `_draw`), background key `properties` → `assets/png/back_city.png`. Button "Недвижимость" sits above "Автомобили" on the game screen; the main game screen shows the owned property's `PropertyArt` in a second frame to the right of the car (grey house placeholder + "нет недвижимости" when owned). Saved as `owned_property`.
- Saves: 5 slots `%APPDATA%\Godot\app_userdata\Бизнесмен\save_%d.json` (user://save_%d.json); `GameState.current_save_slot` (default 1). `SaveManager` API: `save_game(slot=-1)`, `load_game(slot=-1)`, `has_save`, `delete_save`, `get_save_info`, `get_available_slot`, `set_save_dir(dir)` (redirects all slot paths; smoke tests use `user://smoke_test_saves` so they never touch real saves). Save/Save & Exit open a save-slot chooser (autosave writes the current slot each turn); non-empty slots have a "Удалить" button in both the in-game chooser and the main-menu load screen, each guarded by a `ConfirmationDialog`. Settings: `user://settings.json`. Saves persist `game_won` (→ `GameState.has_won`), `owned_car`, and `win_amount`.
- Theme/backgrounds: dark game theme `assets/game_theme.tres` (project.godot `gui/theme/custom`); each screen draws a semi-transparent themed background via `UIBackground.add(self, key, tint)` (`scripts/ui/ui_background.gd`; keys `menu`/`exchange`/`cars`/`enterprises` → `assets/png/back_showroom_.png` for cars, `assets/bg/bg_*.png` for the rest, `STRETCH_KEEP_ASPECT_COVERED` + dark overlay), then a framed `PanelContainer` board (main menu = `CenterContainer`→`PanelContainer`); dialogs centered via `_style_dialog()`.
- Music: `Music` autoload (`scripts/autoload/music.gd`) loops `assets/audio/game_music.wav` (mono 32 kHz 32-bit float, 10 s) via an `AudioStreamPlayer`; **loop is done by replaying on the `finished` signal** — setting `AudioStreamWAV.loop_mode = LOOP_FORWARD` makes playback stop immediately in this Godot build, so never use it. On/off from `Settings.music_enabled` (settings page "Музыка/Вкл" checkbox, saved to `user://settings.json`); `Settings.apply()` calls `Music.set_enabled()`.
- Win condition: reaching `GameState.win_amount` (default `DEFAULT_WIN_AMOUNT=1000000`, player-chosen 50000..1000000 on the "Новая игра" page via a `SpinBox`, clamped) sets `GameState.has_won` (latched) and emits `game_won`; `main_screen.gd` pops the victory dialog (`g_win_*` keys, formatted with `GameState.win_amount`) and calls `SteamAchievements.unlock(...)`. `SteamAchievements` (autoload) is a no-op unless GodotSteam exposes the `Steam` singleton; achievement API name `ACH_WIN_100000`.
- Antimonopoly timers keyed `"<owner>_<type>"` (e.g. `"0_raw"`); fine `0.15 × sum(prices)` if >=2 same type every 2 turns (all owners; popup only for player).
- Exchange screen (`exchange_screen.gd`) is a **two-table board** (side-by-side panels: raw offers + product offers, each with its own header and scrolling list of that kind's lots; the `kind` column is gone). Player info sits in one top row (back button, title, money, inventory) with a second sub-row holding the reference price, car/tram and the `x_stepper_hint` (font 14, right-aligned), which keeps the board inside 1280px. Board margins 20, table separation 16, `COL_SELLER=100`, `COL_ACTION=260`, post-row separation 4, price `SpinBox` 80px. Each panel has its **own post-lot form above its table** (label + qty stepper + price `SpinBox` + "Post"), so raw/product posting is independent; `DEFAULT_QTY=10` (untouched post field re-derives `min(10, stock)` on refresh; clamped to stock/lot). Quantity fields use a custom `_make_stepper` (± buttons, green + / red −, `48×48`) instead of `SpinBox` arrows; click steps by 1, ctrl+click by 10, shift+click by 100 (a small `x_stepper_hint` label under the top row explains this). Columns: price/qty/seller/action; own lots show "Cancel", others show stepper + "Buy".
- i18n: `I18n` autoload registers EN/RU `Translation`s from `I18n.MESSAGES` (keys `m_*` menu, `t_*` type names, `g_*` game screen/dialogs, `e_*` enterprises, `x_*` exchange, `c_*` cars, `ev_<id>_desc/_effect` events). `Settings.apply()` calls `TranslationServer.set_locale(language)`; the settings page rebuilds after "Применить", so switching RU/EN takes effect immediately. UI code uses `tr("key")`; language names stay in their own language ("Русский"/"English").
